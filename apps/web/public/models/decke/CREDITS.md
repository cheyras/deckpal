# Deck-E assets — credits and provenance

Following the precedent set by `apps/web/public/marketing/`: committed binaries
carry a note saying where they came from and how to regenerate them.

These ship to production but are **owner-only**. `/dev/decke` is gated on the
server-verified `owner` flag from `GET /me`, and `vite.config.ts` keeps both
`models/**` and the route's JS chunk out of the PWA precache — which is eager, so
without that exclusion every visitor would pull 6.5 MB into their cache on first
load for a route one account can open. The route's import is lazy, so in practice
only the owner ever fetches any of this.

The character itself is original work by @cheyras, modelled and animated in
Blender. The `$`, `★` and `!` glyphs in the atlas are his own Illustrator
artwork; the spiral and `X` are parametric and the scribbles are generated.

## Regenerating

`playbook.json` is derived — never hand-edit it:

```bash
python apps/web/scripts/decke/gen-playbook.py          # rewrite
python apps/web/scripts/decke/gen-playbook.py --check  # assert it matches its sources
```

`decke.glb` is exported from Blender with **`export_apply=False`**. This is not
optional: with Apply Modifiers ON the glTF exporter emits **zero morph targets**,
silently — no error, no warning, no log line — and every body deformation and
mouth shape on this character is a morph target. The full export call and an
eight-point verification (morph counts, `extras.targetNames` order, the
two-primitive split on `DeckBox_Base`, vertex counts, the node tree, clearcoat,
no animations) is recorded in the session notes.

## Compression, and two things that must not be compressed

`scripts/decke/shrink.mjs` takes the raw export from **7.48 MB to 2.92 MB** —
meshopt geometry, webp textures (q95 for card art, lossless for the grain normal
map), and the embedded copy of the SDF atlas stubbed to a 1×1 pixel because the
runtime replaces both eye materials with a shader that loads the standalone file.

```bash
node apps/web/scripts/decke/shrink.mjs <raw-export.glb> apps/web/public/models/decke/decke.glb
```

Two hard limits, both found by trying:

- **Never Draco, never quantize.** `KHR_draco_mesh_compression` structurally
  cannot carry morph targets, and every body deformation here is one.
  `KHR_mesh_quantization` is subtler and worse: it parks a de-quantisation
  transform on each mesh's *node*, and the rider system writes the whole TRS of
  those nodes, discarding it — `Hinge_Pin_R` inflates into a cylinder wider than
  the character. Quantizing would reach 1.39 MB. It is not worth it. Also never
  run bare `gltf-transform optimize`: `--simplify` defaults on and would average
  away the facial detail this character is entirely made of.
- **The SDF atlas must stay 16-bit.** It is the most obvious 1 MB to save and an
  8-bit greyscale version is 0.18 MB, but the eye shader maps the glyph edge over
  `[0.4985, 0.5020]` — a band 0.0035 wide, narrower than one 8-bit step (0.0039)
  — so the whole antialiased edge would collapse to a single quantisation level.
  `.r` is the glyph, `.g` a second layer, `.b` unused.

Still open: the HDRI could drop to 512×256 if PMREM cost ever matters, though it
does not today — measured 5.8 ms median frame at 390×844, 3× DPR and 6× CPU
throttling, at 37 draw calls and 26.7k triangles. 1024×512 is what three.js's own
docs call the ideal PMREM input size.
