## 2026-09-19 — Release-scoped price-link overlay for 30th Celebration sets (correction)
**Decided by:** price-link correction worker (Claude, z-ai/glm-5.2) on behalf of @cheyras
**Decision:** Add a bounded, source-attributed overlay registry (`apps/sync/src/catalog/releasePriceLinks.ts`) that pins TCGplayer group/product ids for two English sets — `30th` (group 24722, 158 catalog cards, 158 linked) and `30th-c` (group 24837, 30 cards). The importer consumes a single new public boundary, `resolveReleasePriceLink({language,setId,groupId,card,variant,variantCount})`, which returns a verified `(groupId,productId,printing)` triple or `null` to refuse. On refusal the importer keeps the original upstream fields untouched.
**Why (correction of the rejected prior patch):** The prior patch introduced a GLOBAL `COALESCE(EXCLUDED.x, table.x)` for `tcgplayer_group_id`, `tcgplayer_product_id` and `tcgplayer_printing` on every `ON CONFLICT`. That is a stale-id preserver across unrelated sets: a NULL upstream on any set silently keeps whatever was last written to the row, so stale ids survive every future import and future ambiguous variants keep old mappings. Its resolver also keyed on `cardId` only — wrong name, collector number, language, group or printing were not refused — and `mapping.json` claimed "verified 188" while every cardName was `(see TCGdex)` and the evidence directory was empty.
**Narrow no-COALESCE design:** All three columns now write `EXCLUDED` only. The verified value is computed in TypeScript BEFORE the SQL: the set-level `tcgplayer_group_id` uses the scoped static fallback `st.thirdParty?.tcgplayer ?? getOverlay(st.id)?.groupId ?? null` (computed before the INSERT, applied only when upstream is NULL); the per-variant product id is resolved by `resolveReleasePriceLink`. A NULL upstream with no overlay writes NULL — the honest result, not a silent preservation of a stale id. There is no SQL `COALESCE` anywhere in `import.ts` for these columns.
**Resolver identity guard:** `resolveReleasePriceLink` refuses (returns `null`) unless `language==='en'`, `setId` is one of the two covered sets, `card.set.id===setId`, `variantCount===1`, the variant is a supported canonical singleton — either the synthesized singleton `planCardVariants` produces for zero-variant cards OR a real upstream variant carrying the explicit `generated` variantId (the marker TCGdex emits for the canonical generated variant) — with the canonical facet (normal/standard/no subtype/no foil/no stamps; any other real holo/reverse/stamped/oversize/subtype variant, including a future real normal variant WITHOUT the `generated` marker, is refused until separately verified), `variant.tcgplayerProductId==null` (upstream wins), `groupId` is null or equals the overlay group (a conflicting upstream group prevents the product fallback), `card.id` is in the overlay, `card.localId` equals the pinned collector number, and the normalized `card.name` equals the pinned canonical name (NFKD + drop combining marks + curly-apostrophe fold + ♀→F/♂→M + lowercase + whitespace collapse, the explicit Nidoran♀ ↔ "Nidoran F" allowance). The actual upstream 30th-001 card (fetched live) carries a real `variantId:'generated'` variant and is accepted; the synthesized zero-variant shape is also accepted.
**Source authority (8 files captured into the task `evidence/` directory, 2026-09-19):** TCGCSV products + prices for groups 24722 and 24837; TCGdex sets 30th and 30th-c; per-card TCGdex endpoints for 30th-c-019 and 30th-c-020.

**Correction of the prior worker's 30th-126 exclusion (root check bug found):** The prior worker left 30th-126 "Poké Pad" UNLINKED on the grounds that accent stripping was not an allowed source-name normalization. That exclusion was itself the error: the production resolver's `normalizeCardName` already performs NFKD normalization WITH combining-mark removal (`.normalize('NFKD').replace(/[\u0300-\u036f]/g, '')`), so the accented TCGdex "Poké Pad" and the de-accented TCGCSV "Poke Pad" fold to the same `pokepad` — this is accent equivalence, not a force-map. The root acceptance check (`check-price-hardening.py`) had the same bug in its own `norm()`: it called `unicodedata.normalize('NFKD', s)` but failed to drop the combining marks, so it incorrectly rejected the Poké Pad match. Root corrected `norm()` to drop combining characters (mirroring the production resolver) and now requires all 158 main matches; the production source resolver already dropped combining marks correctly and needed no change. This worker restores the one tuple — `30th-126`, localId `126`, the actual accented canonical card name "Poké Pad", productId `716515`, printing `Holofoil` — to the registry. There is no card ambiguity: collector `126/128` matches product `716515` "Poke Pad" in group `24722`, and the names fold equal under NFKD. Runtime guards are NOT relaxed: a wrong name at the same slot is still refused.
**Unresolved gaps:** none. The overlay is deliberately scoped: it does not apply to any other set, any non-English language, any multi-variant card, or any variant that is not the supported canonical singleton. Future nonsupported/multiple variants are refused until verified against source.
**Honest idSource/confidence:** The overlay product ids are not from upstream `thirdParty.tcgplayer` (TCGdex publishes none for these sets) but from a curated, source-verified registry mapped at the variant granularity. Within the existing `'variant' | 'card' | 'none'` enum, `'variant'` is the least-wrong choice (a per-variant product id) and `idConfidence: 100` reflects confirmation against the authoritative TCGCSV source the price sync joins on; the provenance is documented here and in the file header, not the silent stale-id preservation the prior COALESCE produced.
