## 2026-11-27 — Printed set-code marks drawn as the card prints them
**Decided by:** Chey (via Claude Opus 5.5)

**Decision:** The owner, after #409 made set tiles draw their code as text: "we should make it look like the real thing." So the tile now draws the printed mark itself, not a generic pill.

- **`PrintedSetMark`** (`components/PrintedSetMark.tsx`, geometry in `components/printedMark.ts`) draws the plate as printed:
  - a fixed 1.75 : 1 black plate, corner radius 0.135 of its height;
  - a black rim and a white keyline (each about 1/20 of the height) just inside the edge;
  - white capitals in a condensed extra-bold grotesque, cap height 0.58 of the plate;
  - "EN" at 0.43, on the code's baseline, against the right edge, with the code from a fixed left margin. A wide code (TWM) is set tighter, because the plate never grows.
- **The letters are 36 original vector outlines (A–Z, 0–9), not a font.** They are generated by `apps/web/scripts/build-printed-glyphs.mjs` into `components/printedMarkGlyphs.ts`, about 3.5 kB gzipped.
- **`SetSymbolTile` moved out of `ui.tsx` into `components/SetSymbolTile.tsx`.** `ui.tsx` is in the entry chunk; the tile and its outlines now load with the pages that show a set. The critical path went from 222.1 to 221.2 kB.
- **Per placement:**
  - Series rows (36px), the set header (40px) and the series index (48px) show the plate with EN, on the white tile.
  - The card sheet (28px) shows the card's own print line, `[H] [SCR EN]`. That is the card's regulation box (`regulationMark` from the card) beside the plate. The tile widens to hold it.
  - Set-level tiles never show a regulation mark.
- **Hinting.** The rim and keyline are held at no less than one device pixel. They are drawn at their true weight on 2× and 3× screens and do not smear into grey at 1×.
- **Coverage.** Every code was checked against crops of real cards from the image tier: 2–6 cards per set, across 33 sets.
  - All 26 codes the scanner's table (`scan/ocr/codes.ts`) supplies are right.
  - Four sets print a code that table lacks or misspells. They are drawn from `CODES_READ_FROM_CARDS` in `lib/printedSetCode.ts`:
    - `2023sv` M23 and `2024sv` M24. The table has MCD23 / MCD24, which are not printed.
    - `2026me` M26.
    - `30th` 30C.
  - Still excluded: `svp` keeps its Black Star, although it prints SVP. `mfb` prints no code; checked on four cards. `30th-c` reprints keep their original print lines, so the set has no single code.
- **Gallery.** `/design` has three entries:
  - `SetSymbolTile`, in its own gallery file;
  - `PrintedSetMark`, shown on the dark surface;
  - "PrintedSetMark — real vs ours". It crops each card's print line live from its art in the image tier and shows ours beside it at the same scale, with an overlay toggle. It covers SV, ME, energy, promo, McDonald's, 30th, and an ME gold knock-out.

**Why:**
- **What the real mark is, measured.** The sharpest copy the app holds is the 228px MEP set symbol, the official plate artwork. It gave:
  - the plate's proportions, rim, keyline and radius;
  - stems at 0.17 of the cap height and horizontals at 0.14;
  - E 0.33 cap wide, P 0.46, and M 0.60 at the top and 0.73 at the foot (its sides splay).
  
  600px scans of every SV and ME set confirmed the plate size (38 × 22 px), the cap height and the EN placement. An overlay of ours on the scans at 4× lines up.
- **Scarlet & Violet and Mega Evolution print the same mark.** On standard cards the plate, keyline, face and proportions match to the pixel; only the regulation letters move on (G/H/I to I/J). What differs is per-card finish:
  - ME's gold Mega Hyper Rares print the mark knocked out, so the gold shows through the letters and keyline. SV's gold cards keep white ink.
  - White Flare's special rares print it in grey.
  - 30th Celebration's R/RGB card prints a green plate.
  
  Those belong to one printing, not to a set, so the tile draws the standard mark.
- **Outlines, not a font.**
  - The face is near Futura Condensed ExtraBold, which is not free.
  - A free condensed webfont would be a second font request for three letters a tile, and would flash the fallback face on first paint. It would also only approximate the face.
  - Outlines for a fixed alphabet render on the first frame, ride in a lazy chunk, and are drawn to the measurements.
- **EN on set tiles.** The plate is a fixed size, so EN takes the margin and not the code's height. The code's cap height is the same with or without EN. At 2× and 3× EN reads; at 1× it is texture, the way it is on the card. The owner asked for the real thing, and on a card EN is always there.
- **Regulation mark only on the card sheet.** It is a property of a card, not of a set: sv07 prints G and H. The card sheet is also the only place the app shows a card's regulation mark beside its set.
- **The four extra codes.** Their upstream symbols are small rasters (43–150px wide) of the same plate, with the same smudge #409 fixed for the others. The codes were read off 3–6 cards each.

**Implications:**
- **A new set that prints a code** needs a row in `scan/ocr/codes.ts`; the tile picks it up. A row in `CODES_READ_FROM_CARDS` is only for a code the scanner's table lacks. A test fails once the scanner's table agrees, so the override is deleted rather than left to drift.
- **For the scanner work:** `scan/ocr/codes.ts` should gain `30C` (`30th`) and `M26` (`2026me`), and its McDonald's rows should read `M23` / `M24`. Cards print those, so a scanner read of "M23" matches no row today. That is the same shape of miss as DLR before 2026-11-25.
- **Glyphs:** change `scripts/build-printed-glyphs.mjs` and re-run it. Never hand-edit `components/printedMarkGlyphs.ts`. A code with a character outside A–Z and 0–9 cannot be drawn, and a test checks every code in the table.
- **`SetSymbolTile` import:** import it from `components/SetSymbolTile`. Re-exporting it from `ui.tsx` would put the outlines back on the critical path.
- **Not touched:** DeckBuilder's inline `PrintedSetCode` chip, an outlined 14px text tag. It is a separate placement and could adopt `PrintedSetMark` later.
- **Wiki:** UI-Spec §3.7 (the set-symbol tile) describes the image-only tile. It needs an "OURS, 2026-11-27" note when this merges, along with the Decision Log and Contribution Record.
