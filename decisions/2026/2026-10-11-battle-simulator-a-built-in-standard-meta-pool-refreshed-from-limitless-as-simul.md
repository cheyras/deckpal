## 2026-10-11 — Battle simulator: a built-in Standard meta pool, refreshed from Limitless, as simulate opponents
**Decided by:** @cheyras (a player with one deck has nobody to play against; wanted current Standard meta decks as built-in opponents); built by Claude Sonnet 5.5.

**Decision:** `POST /decks/simulate` and `simulate_battles` can play against a built-in pool of current Standard decks, one representative 60-card list per archetype, stored as data in `packages/sim/src/meta/data.ts` (typed accessors `META_POOL`, `metaDeck`, `topMetaDecks`, `metaLabel`) and regenerated by hand with `node --import tsx scripts/meta-refresh.ts` from `packages/sim`.

- **Source.** Limitless's public tournament API (`play.limitlesstcg.com/api`: the events list and each event's standings): read-only GETs, one at a time with a pause and a User-Agent naming DeckPal, backing off on a 429. Nothing calls Limitless at request time; the app serves the committed data, and `asOf`, the window and the source ride along in the file and in every report's notes.
- **Selection rule.** Events: Standard, in the last 21 days, 32+ players. Share: an archetype's players over all players with an archetype in those events. The top 12 archetypes that yield a usable list, in share order. Representative list: among the archetype's decklists from its three largest events, the best match win rate (ties count half, at least 6 rounds played), then the better placing, then the larger event, then the later date. If that list cannot be mapped or is not legal, the next candidate is tried (five at most) and every failure is printed; an archetype with none left is skipped and named. Nothing is dropped silently.
- **Card mapping.** A Limitless line (PTCG Live set code + number) maps to a catalogue id through the deck importer's own alias table (`apps/api/src/deck/data/ptcgl-set-alias.json`), with the importer's name-in-set fallback; basic Energy maps by name. Ids the sim's frame snapshot lacks (it is not every Standard card) are kept and flagged `unverified`; the first pool's four were checked against TCGdex by hand, and the API re-checks every pool id's catalogue name at play time and refuses a list whose id is a different card. `30C` (30th Celebration) is a Limitless-only code the importer's table lacks, supplied inside the script.
- **Legal 60-card Standard deck.** Exactly 60 cards, a Basic Pokémon, at most 4 per name (basic Energy exempt), at most one ACE SPEC, and every card legal by NAME in regulation marks H, I or J: an older print of a reprinted card passes, as it does in play.
- **Anonymity.** The data keeps the archetype, the event name and date, the record and the placing. No player names, countries or handles.
- **API.** The opponent value `meta` is the top 6 pool archetypes; `meta:<name>` is one (id or name, a unique fragment is enough; unknown or ambiguous is a `400` that lists the archetypes). An archetype name that matches no saved deck also resolves to the pool, but a saved deck always shadows the pool, so a player's own "Dragapult" is never silently replaced. With no opponents named and no other saved deck, the default is the top 6 pool decks instead of a `400`. Every existing bound stands: 1 to 8 opponents (`meta` counts as 6), the 25 s budget and hard deadline, the games cap, the per-account and per-instance run gate, and the connection released before any game. A pool opponent is labelled `Meta: <archetype> (Limitless online, <event date>, <record>)` and a note states the window and as-of date. Frames come from the catalogue exactly as a saved deck's do.
- **Tool.** `simulate_battles` accepts `meta` / `meta:<archetype>` in `opponents` (passed to the API as written, without a deck lookup; a name that matches none of the user's decks is also left to the API), says in its schema and description that the pool is a hand-refreshed snapshot with an as-of date, and stays read-only. Deck-E's iterate and build pathway texts mention the pool.

**Why:** The simulator's opponents were only the caller's own saved decks, so a player with one deck, or a new player, had nobody to test against, and "how does it do into the meta" had no honest answer. A pool in the repo is reviewable, deterministic, free of a runtime dependency on a third party, and costs nothing per request; refreshing by hand keeps Limitless's traffic small and puts a person's eyes on the diff.

**Implications:**
- The pool ages. Re-run `scripts/meta-refresh.ts` (about 10 minutes the first time, since it fetches ~130 events slowly; `--cache <dir>` re-uses fetched standings), read the printed skip list, run the sim and API suites, and commit `data.ts`. `--dry-run` prints without writing.
- The tests (`packages/sim/src/__tests__/meta-pool.test.ts`) check the committed pool is well formed, legal and plays in the engine, and the refresh logic runs on a recorded fixture with no network. A new set whose cards the alias table lacks will make lists using it skip, loudly, until the table has it.
- A pool deck is one list per archetype from online events, not the whole archetype and not the ladder: reports must keep calling these a snapshot, and a saved scouting list of a real opponent is still the better opponent.
- A sim snapshot that lacks a Standard card does not block a list, but only the API's runtime name check stands behind an `unverified` id. Keep that check.
