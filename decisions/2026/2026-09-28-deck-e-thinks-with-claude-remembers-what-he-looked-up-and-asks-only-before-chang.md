## 2026-09-28 — Deck-E thinks with Claude, remembers what he looked up, and asks only before changing your data
**Decided by:** @cheyras, on a diagnosis of his own Deck-E conversations (roadmap/plans/decke-chat-overhaul/PLAN.md); built by Claude Opus 5.5 directing Codex workers.

**Decision:** Deck-E's conversation runs on Claude Sonnet 5.5 (`anthropic/claude-sonnet-5.5`), which plans decks, analyses collections and recovers from failures in its own streamed loop. The three deep sub-agents (`plan_deck`, `analyze_collection`, `write_strategy_guide`) are gone. Web research stays a separate tool, renamed `web_research`, with a reader-facing `purpose`, no approval card, and source URLs streamed to the browser for display (the model still sees hosts only). The browser replays FULL tool results for the six most recent assistant turns (12,000 characters each), one-line records beyond that, and every decline as a real `output-denied` part for the whole window; the current turn is capped at 240,000 characters. Approval is asked only before a write. New tools: `check_deck` (read-only `POST /decks/check`) verifies a list — size, format rules, evolution lines, what the reader owns, what the rest costs — and `showDeck` shows it as cards with a Save button that imports it in one transaction. The chat shows one live activity line per run of tool calls (icon per tool kind, label that updates in place, tap to expand), sources with favicons, and Deck-E's body follows the work step by step instead of idling. The system prompt was rewritten around talk-versus-act judgment, memory, deck building and honest failure.

**Why:** In the owner's own chats (2026-08-26 → 2026-09-28) Deck-E researched the same meta nine times in one conversation, reported research as "already declined" when nobody had declined anything, asked the reader how many Rare Candy they owned, built Litwick → Lampent → Delphox from memory after `plan_deck` timed out, and saved a 65-card deck. The causes were structural, which is why a month of patches did not hold: (1) between turns the browser replayed one line per tool call, and for research that line was the untrusted-content frame, so findings never reached the next turn while the prompt demanded "look it up first"; (2) the model doing the talking was a non-reasoning model chosen for ~1¢ a turn, while the capable model ran only inside approval-gated sub-agents with a 210-second clock; (3) one approval card priced a 4-credit lookup like a 75-credit plan and described every research call as "research the meta"; (4) a classifier added to hear refusals in words (#225) read "cards I already have" and "make it my own" as "don't research". Each earlier fix landed where a symptom showed rather than where the fact was lost — the same shape the navigation pass (#243, #258) broke by changing what the model can do and testing the real multi-turn path.

**Implications:**
- Cost per turn rises (Sonnet 5.5: $2 / $10 per M tokens, $0.20 cached reads) but waste falls: the broken 13-turn conversation cost ≥114 credits, 75 of them for a `plan_deck` that timed out and charged anyway. Credits still charge flat per leg in this change; settling every charge on actual Gateway cost (the owner's ruling: "credits which map to actual money") is the next PR — design in the overhaul plan, migration 078.
- Declines are exact and conversation-long (same tool, same arguments), not guessed from wording. Spoken-decline classification is removed; Jev's reflex no longer forces a tool for Anthropic models, because forced tool choice and thinking do not mix.
- `web_research` failures and meter limits say NOT RUN, never REFUSED — only the reader refuses.
- The chat model's declared fallback (`google/gemini-2.5-flash`) is now actually used, through the Gateway's model routing.
- `scripts/decke-replay-probe.mjs` replays the owner's real conversations against any model with fixture tools and scores re-research, tools on feedback turns, `check_deck` before `showDeck`, 60-card lists, text-dumped decklists, false refusals and cost; `scripts/decke-leg-smoke.mjs` checks multi-leg continuations with a thinking model.
- Open, not fixed here: the `decks`/`battle_logs` "Internal server error" seen in production has no established root cause (the adapter now names the tool and gives a non-leaky reason); approvals are unsigned on deployments without `DECKE_APPROVAL_SECRET` (set in production; a self-host hardening item).
